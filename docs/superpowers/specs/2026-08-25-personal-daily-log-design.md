# 个人日常日志 Web 应用设计规格

> 状态：设计基线 v1.0
> 日期：2026-08-25
> 目标：为个人用户提供可跨设备访问的日常日志记录与回顾能力

## 1. 范围与目标

这是一个独立的个人日志 Web 应用，使用 Vue 3 和 Java 构建。用户通过浏览器登录后，可以创建、编辑、删除和回顾自己的日常日志。

### 1.1 已确认目标

- 使用浏览器访问，支持电脑和手机等多设备。
- 当前只有一个个人账户，不开放普通注册，也不实现多用户权限管理。
- 首次启动时创建唯一账户，之后使用用户名和密码登录。
- 日志支持日期、标题、正文、标签、心情、天气和地点。
- 首页以按日期倒序的时间线为主。
- 支持按日期、心情、标签和关键词筛选日志。
- 天气和地点由用户手动录入。
- 心情使用预设选项。
- 标签由用户自由创建和选择。
- 生产数据库使用 MySQL。

### 1.2 MVP 不包含

- 图片、文件、语音和富文本附件。
- 外部天气 API、地图 API 或定位服务。
- 第三方登录、邮箱验证和找回密码。
- 多用户注册、角色和权限管理。
- 全文搜索引擎、复杂统计和情绪趋势分析。
- 回收站与日志恢复功能。

## 2. 总体架构

采用模块化单体架构：

```text
Vue 3 + Vite
    │
    │ REST /api
    ▼
Spring Boot 3 / Java 17
 ├─ auth       用户初始化、登录、登出、会话
 ├─ diary      日志新增、编辑、删除、详情
 ├─ taxonomy   标签和预设心情
 └─ query      时间线、日期范围、筛选
    │
    ▼
MySQL
```

### 2.1 前端

- Vue 3 + Vite。
- 按页面、业务模块和 API 客户端组织代码。
- `/api` 作为后端请求前缀。
- 不把日志正文或认证信息保存到 LocalStorage。
- 在桌面端使用居中的内容区和筛选区域；手机端将筛选区域改为抽屉或弹层。

### 2.2 后端

- Spring Boot 3 + Java 17。
- 使用 Spring Web 提供 REST API。
- 使用 Spring Security 处理密码校验、会话认证和 CSRF 防护。
- 使用 JPA 或等价的参数化数据访问方式访问 MySQL。
- 使用 Flyway 管理数据库迁移。
- 业务模块通过应用服务隔离 Controller、领域规则和持久化逻辑。

### 2.3 部署

- 使用 Docker Compose 编排 Java 应用和 MySQL。
- 前端构建为静态资源，由反向代理或后端静态资源服务提供。
- 生产环境通过 HTTPS 运行，以满足 Secure Cookie 的要求。
- 数据库备份属于部署运维范围，不在日志业务模块中实现。

## 3. 认证与会话

### 3.1 账户初始化

- `POST /api/auth/setup` 仅在 `users` 表为空时可用。
- 初始化操作在事务中创建唯一用户。
- 数据库唯一约束和服务端检查共同防止重复初始化。
- 初始化成功后接口不再接受后续创建请求。

### 3.2 登录会话

- 密码只保存 BCrypt 哈希，不保存明文。
- 登录成功后生成不可预测的会话 Token。
- 服务端只保存 Token 哈希，原始 Token 通过 HttpOnly Cookie 返回。
- Cookie 使用 `HttpOnly`、`Secure` 和 `SameSite=Lax` 属性。
- 每台设备可以拥有独立会话；退出一台设备不影响其他设备。
- 会话具有可配置的过期时间，并记录最后访问时间。
- 后续可在设置页增加查看和撤销其他设备会话的能力。

### 3.3 认证接口

- `POST /api/auth/setup`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`

登录接口需要有失败频率限制。所有日志 API 都必须从当前认证会话取得用户身份，不能接受前端提交的任意 `user_id` 作为权限依据。

## 4. 数据模型

### 4.1 用户与会话

`users`

- `id`
- `username`，唯一
- `password_hash`
- `created_at`
- `updated_at`

`sessions`

- `id`
- `user_id`
- `token_hash`
- `device_label`
- `expires_at`
- `last_seen_at`
- `created_at`

### 4.2 日志与标签

`diary_entries`

- `id`
- `user_id`
- `entry_date`，日志所属日期
- `title`
- `content`
- `mood_code`
- `weather`
- `location`
- `created_at`
- `updated_at`

`tags`

- `id`
- `user_id`
- `name`
- `created_at`

`entry_tags`

- `entry_id`
- `tag_id`

### 4.3 数据规则

- 同一天允许存在多条日志。
- `entry_date` 使用日期类型，与创建时间分开保存。
- 时间线按 `entry_date DESC, created_at DESC` 排序。
- 心情使用后端预设编码，例如 `happy`、`calm`、`anxious`、`sad`、`tired`。
- 标签名称在同一用户下不能重复；保存前去除首尾空格并做字符规范化。
- 所有业务表保留 `user_id`，为未来用户扩展保留数据隔离边界。
- 标题、正文、天气和地点均由后端校验长度与格式；前端提供即时校验。
- MVP 删除日志前二次确认，删除后不提供回收站恢复。

### 4.4 索引

- `diary_entries(user_id, entry_date, created_at)`
- `diary_entries(user_id, updated_at)`
- `tags(user_id, name)` 唯一索引
- `entry_tags(entry_id, tag_id)` 唯一索引
- `entry_tags(tag_id, entry_id)` 查询索引

MVP 先使用 MySQL 参数化查询实现标题和正文关键词筛选，暂不引入独立搜索引擎。

## 5. 页面与交互

### 5.1 页面

- `/login`：用户名密码登录。
- `/timeline`：按日期倒序展示日志，并提供筛选和搜索。
- `/entry/new`：创建日志。
- `/entry/:id`：查看、编辑和删除日志。
- `/settings`：账户和会话相关设置的扩展入口。

### 5.2 时间线

顶部提供新建日志、日期范围、标签、心情和关键词筛选。主体按日期分组展示日志卡片，每张卡片显示标题、正文摘要、心情、天气、地点和标签。

需要覆盖以下状态：加载中、无数据、网络错误、筛选无结果和可重试状态。创建成功后返回时间线，并定位到新建日志。

### 5.3 日志表单

字段包括日期、标题、正文、心情、天气、地点和标签。日期默认今天，心情以预设选项展示，标签输入支持已有标签自动补全和新标签创建。

标题和正文不能为空。提交期间禁用保存按钮，防止重复提交。离开存在未保存内容的页面时提示确认。编辑页的删除操作必须二次确认。

## 6. API 设计

### 6.1 日志接口

- `GET /api/entries`
- `POST /api/entries`
- `GET /api/entries/{id}`
- `PATCH /api/entries/{id}`
- `DELETE /api/entries/{id}`

列表接口支持：

```text
from=2026-08-01
to=2026-08-31
mood=calm
tag=工作
keyword=项目
page=0
size=20
```

列表返回分页结构：

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "total": 0,
  "hasNext": false
}
```

### 6.2 标签和心情接口

- `GET /api/tags`
- `POST /api/tags`，可由日志保存流程按需创建
- `GET /api/moods`

心情列表由后端提供，保证前后端使用同一组编码和显示名称。

## 7. 错误处理

API 使用统一错误结构：

```json
{
  "code": "ENTRY_NOT_FOUND",
  "message": "日志不存在",
  "traceId": "..."
}
```

主要状态码：

- `400`：请求参数或表单校验失败
- `401`：未登录或会话失效
- `403`：无权限
- `404`：日志或标签不存在
- `409`：标签重复等业务冲突
- `429`：登录尝试过于频繁
- `500`：服务器内部错误

前端对未登录请求统一跳转登录页，对字段校验错误显示在对应字段旁；服务端错误显示可读提示并保留重试入口。服务端日志记录内部异常和 Trace ID，但不记录密码、会话 Token 或日志正文。

## 8. 测试与验收

### 8.1 后端验收

- 首次账户初始化只能成功一次。
- 登录、登出和会话过期行为正确。
- 多设备会话互不影响。
- 日志可以完整新增、查询、编辑和删除。
- 同一天多条日志的排序正确。
- 日期、心情、标签和关键词筛选正确。
- 未登录不能访问日志。
- 用户不能访问其他用户的数据。
- 重复标签和非法输入会被拒绝。
- 数据库迁移可以从空库完整执行。

### 8.2 前端验收

- 登录流程可用。
- 时间线正确展示和分页。
- 新建、编辑和删除日志可用。
- 筛选条件可以组合使用。
- 加载、空状态、错误状态和保存成功状态正确显示。
- 桌面和手机宽度下布局可用。

### 8.3 交付标准

用户能够创建唯一账户，在电脑和手机浏览器登录，记录包含日期、标题、正文、标签、心情、天气和地点的日志，并按日期、心情、标签和关键词回顾自己的内容。

## 9. 后续增强方向

以下内容不属于当前 MVP，但架构应为其保留扩展空间：

- 邮箱或第三方登录。
- 会话管理和退出所有设备。
- 图片、文件和语音附件。
- Markdown 或富文本正文。
- 自动获取天气和地图地点。
- 回收站、恢复和版本历史。
- MySQL 全文索引和统计分析。
- 多用户、角色和权限管理。
